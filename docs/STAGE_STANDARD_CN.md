# 各癌种统一阶段与交付规范 v1

用户要求：每阶段结果上传GitHub，各癌种记录顺序和格式一致。两个账号均执行本规范。

## 固定展示顺序

|stage_id|阶段|必需记录|
|---|---|---|
|01_CAMP|冻结CAMP发现结果|全量/显著数、原效应/P/q、来源与版本|
|02_MAPPING|直接代谢物—基因映射|特征数、去重关系数、基因数、来源与未映射原因|
|03_PATIENT|患者/标本内RNA与代谢关联|统计单位、实际n、效应/区间/P/q、完整检验族|
|04_ROBUSTNESS|稳健性及协变量分析|可用性子集、影响点、协变量、复用/新增统计范围|
|05_FUNCTION|功能干预与依赖证据|适用模型数、干预方向、出处、反证、缺项|
|06_EXTERNAL|外部代谢/蛋白等补充|身份与样本独立性、覆盖、效应、混杂及适用范围|
|07_INTEGRATION|全候选比较与分层|完整候选、支持/反证、研究增量、当前决定及下一步|

这是报告与登记顺序，不是串行计算关卡；功能和外部分析可以提前并行。无数据阶段仍登记，不为补齐目录做无意义分析。

癌种名称固定为BRCA、COAD、GBM、PDAC、PRAD、ccRCC；跨癌汇总按该顺序。不得把不同癌种强行使用相同模型/阈值；具体方法必须依据设计并记录。

## 新增结果目录

`results/<CANCER>/<stage_id>/<RUN_ID>/`

一个运行涉及多个阶段：主要数值只保存一份，其他阶段索引引用相同路径，不复制为独立证据。RUN_ID使用UTC日期时间加简短任务名，每次唯一。历史目录保持原样，以阶段索引接入。

每次交付包括：

1. `README_CN.md`：按“本轮问题→输入与范围→实际结果→新手解释→限制/反证→当前决定→下一步→复现命令”固定顺序。
2. `results.tsv`或有意义的明细文件：完整可计算和不可计算项目均保留。
3. `analysis_spec.json`：分析版本、参数、统计单位、检验族、种子和软件版本。
4. `source_manifest.tsv`：来源路径/URL、版本、SHA256；不含凭据。
5. `validation.json`：实际验证结果及未验证事项。
6. 可运行脚本及仓库路径；阻塞批次交付错误/状态记录，不伪造空数值结果。

## 字段顺序

阶段索引使用`templates/stage_index.tsv`表头，保存在`coordination/stages/<CANCER>.tsv`。每行表示一个阶段的一次交付，同一运行可登记多阶段；按stage_id、run_id排序。每癌种负责人只更新自己的索引，跨癌合并时只读汇总。

新增统计表的公共前缀字段使用`templates/statistical_result.tsv`，分析专属字段追加在末尾。字段不适用填NA并解释，效应尺度须单列；RNA差异、相关、功能分数不能混作同一效应。历史表以文档明确字段映射，不修改冻结列。

统一状态：`DONE`（该行范围全部完成）、`PARTIAL`、`NOT_RUN`、`NOT_EVALUABLE`、`ACCESS_BLOCKED`、`NEEDS_REVIEW`。缺值写NA/空值并在reason说明；未测不写0，未完成不写阴性。

## 每批上传与验收

运行完成→必要数值核查→更新该癌种阶段索引和报告→检查公开文件→commit→push→核对远程提交→向用户提供GitHub结果链接与未完成事项。已有正常登录授权，无需每批重复询问是否上传。

数据驻留规定不变：只上传脚本、参数、汇总与文献取证；逐患者测量、完整样本映射、原始矩阵、凭据留服务器。阶段完成不等于整癌种完成。

交付提交号从Git历史和运行manifest查询，不把本次提交号写入本次提交造成自引用。分支上传即为GitHub可查；合并状态另行明确，不将尚未合并结果说成main已有。
